# 高二4班 · 零诊成绩报告

面向高二4班的移动端成绩查询与零诊成绩报告页面。学生输入姓名和查询识别码后，可以查看个人总分、班级/年级位置、分科成绩、分数线参考和趋势信息。

> 在线页面：[打开成绩查询页面](https://yusheng266186-beep.github.io/grade-query/)
> 发布工作台：[打开成绩发布工作台](https://yusheng266186-beep.github.io/grade-query/publisher.html)
> GitHub：[查看源代码](https://github.com/yusheng266186-beep/grade-query)

## 项目定位

这是一个轻量、无后台依赖的静态成绩报告网页，配套一个浏览器端发布工作台。每次考试只需填写模板，导入工作台后即可校验、合并历次考试、逐条前端加密，并下载或一键提交 GitHub。

当前页面标题为“高二4班 · 零诊成绩报告”，仓库中包含：

- 查询页面与成绩报告页面；
- `publisher.html`：模板导入、校验、合并、加密和 GitHub 一键发布；
- data/ 数据资源目录；
- `templates/`：Excel、CSV、JSON 三种输入模板；
- `docs/INPUT_FORMAT.md`：字段和更新流程说明；
- 家长查询二维码图片；
- GitHub Pages 静态部署文件。

## 主要功能

- 通过姓名和查询识别信息进入个人报告；
- 查询页优先读取 `data/grade-data.v2.json`，同时兼容旧版逐文件加密数据；
- 发布前显示合并结果与覆盖提示，发布包带有版本编号和 SHA-256 校验摘要；
- 展示总成绩、班级位置、年级位置等核心结果；
- 展示各学科分数、排名及分数线状态；
- 用报告卡片区分重点信息、达线情况和待提升科目；
- 支持趋势图或历史信息区域，便于观察成绩变化；
- 适配手机屏幕，也可以在桌面浏览器中打开；
- 手机端支持清空输入、键盘下一步、加载反馈、回到顶部和继续查询；
- 页面内置 noindex、nofollow 等元信息，降低被搜索引擎收录的概率。

## 每次考试的发布流程

1. 打开 [成绩发布工作台](https://yusheng266186-beep.github.io/grade-query/publisher.html)，下载 `templates/exam-template.xlsx`。
2. 填写本次考试的考试信息、科目线和学生成绩；空白会被识别为缺失，数字 `0` 会保留，总分留空时自动计算。
3. 导入模板，修正工作台列出的错误；如果要保留历史趋势，先导入上一次生成的 `grade-project-*.json` 项目备份。
4. 点击“生成加密发布包”。工作台会为每位学生生成独立的 AES-GCM 加密记录。
5. 输入只允许修改 `yusheng266186-beep/grade-query` 内容的 Fine-grained Token，点击“一键上传并发布”。工作台会把 `data/grade-data.v2.json` 和 `data/version.json` 作为一个提交上传到 `main`，GitHub Pages 随后自动刷新。
6. 把页面地址发给家长：<https://yusheng266186-beep.github.io/grade-query/>。

项目备份是下一次合并历史考试所需的明文工作文件，只保存在本地，不上传到 GitHub。具体字段见 [输入格式说明](docs/INPUT_FORMAT.md)。

## 使用方式

### 在线使用

打开 Pages 地址，在查询页填写页面要求的信息，点击“查看成绩报告”。

### 本地预览

这是一个静态网页，不需要安装 Node.js 或构建工具。下载仓库后，直接用浏览器打开 index.html 即可预览。

如果浏览器对本地文件的脚本或数据加载有限制，可以在仓库目录启动静态服务器：

    python -m http.server 8080

然后访问：

    http://localhost:8080/

## 数据与隐私

这是最需要注意的部分：

1. GitHub Pages 是公开网页，任何知道地址的人都可能访问页面。
2. 姓名、学号、成绩、排名等都属于敏感的个人教育信息。
3. 页面上的“noindex”不是访问控制，也不能防止别人通过链接访问。
4. 当前工作流按你的要求采用前端加密：发布包中不写入学生明文报告，查询时在浏览器本地解密。
5. 前端加密不等同于后台访问控制；如需更高等级的隐私保护，应迁移到私有仓库或带认证的系统。
6. Fine-grained Token 只在发布工作台当前页面内存中使用，上传结束后会清空输入框，不要把 Token 写入模板、项目备份或仓库。

## 更新成绩数据时的建议

- 先在本地备份原始数据，再制作脱敏副本；
- 保持页面脚本当前使用的数据格式；
- 至少测试一个存在记录、一个不存在记录和一个字段不完整的查询；
- 检查移动端显示、分数线显示和趋势图是否正常；
- 确认公开分支中没有遗留真实姓名、学号或原始 Excel 文件；
- 更新完成后再推送到 Pages。
