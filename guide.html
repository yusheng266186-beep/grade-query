GRADE QUERY · GUIDE

填好一份模板，
完成一次安全发布

优先使用 Excel 模板。工作台会在浏览器本机读取、校验、合并历史并加密，只有加密后的查询数据会上传到 GitHub。

01 · FILL填写模板删除示例学生，填本次考试数据。
02 · REVIEW导入校验按错误提示定位并修正原表。
03 · BACKUP保存项目备份供下次考试继续合并历史趋势。
04 · PUBLISH一键发布生成加密包并提交 GitHub Pages。

每次考试怎么操作

  1. 在发布工作台下载 Excel 模板，不要修改四个工作表名称和第一行表头。
  2. 在“考试信息”“科目分数线”“学生成绩”中填写数据；“知识点失分”可不填。
  3. 删除模板里的 TEST001、示例学生等示例行，再保存 Excel。
  4. 从第二次考试开始，先选择上一次下载的 grade-project-*.json，再导入本次 Excel。
  5. 导入后先处理所有红色错误。黄色提醒不阻止发布，但应逐条确认。
  6. 学号 / 查询识别码请使用 8 位以上随机字母数字组合（发布台有“为空/弱识别码生成随机码”按钮）；不要用身份证号或短学号，公开页面上的数据可以被离线穷举，识别码越随机越安全。
  7. 点击“生成加密发布包”，随后点击“下载项目备份”并妥善保存。
  8. 输入 GitHub Fine-grained Token，点击“一键上传并发布”。发布包采用 v3 加密（记录地址与密钥同源于 24 万次 PBKDF2 派生，离线穷举成本极高）。
  9. 首次发布 v3 数据时，保持勾选“随本次发布删除旧版数据文件”——旧版文件使用弱寻址，v3 上线后应清除。页面显示“发布完成，可以查询”后，再把查询链接发给家长。

同一个“考试编号”再次导入会整场覆盖旧记录，适合修正已发布的数据；新考试必须使用新的编号。

Excel 四个工作表

1. 考试信息

字段是否必填填写要求
考试编号是唯一且稳定，例如 2026-zero；同编号表示覆盖。
考试名称是家长查询页中显示的名称。
考试日期建议填写YYYY-MM-DD，例如 2026-08-13。
排名范围建议填写city / 全市、school / 校内、class / 班级。
班级名称是例如“高二4班”。
特控线、本科线否本次总分线；留空时不显示对应线差。
备注否例如“物理类”。

2. 科目分数线

科目键固定为 chinese、math、english、physics、chemistry、biology。满分必须大于 0；各科特控线、本科线可留空。

3. 学生成绩

字段填写要求空值处理
学号 / 查询识别码必填且不可重复；家长查询时使用。不可留空。
姓名必填；须与家长输入完全一致。不可留空。
班级可为学生单独填写。留空时使用考试信息中的班级。
总分应处于所有科目满分之和范围内。留空时按已填写科目自动合计。
全市 / 校内 / 班级排名只能填正整数。没有该排名范围时留空。
各科分数必须在 0 到该科满分之间。0 是有效分数；空白才是缺失。
各科排名只能填正整数。可留空。

4. 知识点失分（可选）

每行填写“学号、科目键、知识点、题号、失分”。学号必须存在于本次学生成绩中，失分不能为负数；中文科目名也可自动识别。

发布前最后检查

  • 示例学生已全部删除
  • 错误数量为 0
  • 考试编号没有误覆盖旧考试
  • 缺席学生与新增学生数量符合预期
  • 项目备份已下载到本机
  • Token 仅有目标仓库 Contents 读写权限
  • 发布状态显示 Pages 已读取本次版本
  • 用一位测试学生实际查询成功

项目备份包含明文成绩。只保存在自己的电脑或加密存储中，不要把它上传到公开仓库，也不要发给家长。

Token 权限

在 GitHub 创建 Fine-grained Token 时，Repository access 只选择 yusheng266186-beep/grade-query，Repository permissions 只开启 Contents: Read and write。工作台上传结束或失败后都会清空 Token 输入框。
